# 计划驱动的子代理协作

主代理负责计划、分工、上下文交接、跨步骤决策和最终验收；计划中的每个执行步骤必须交给一个专属子代理。子代理模型和推理强度由用户选择，可统一指定，也可按步骤或角色覆盖。主代理保持用户当前选定的模型。

## 先确定本次范围

- 用户只要求生成或重写计划时，优先使用可用的 `multi-step-plan`；未安装该 skill 时也可以直接完成规划。只做计划及必要的只读调查/审查，不启动实现、训练或实验。
- 用户要求按计划执行时，读取现有计划并实施；不因本 skill 再增加一轮批准流程。沿用本次对话中已有的授权和最新约束。
- 优先更新已有计划，保留一个清楚的执行入口。步骤数量随任务决定，不把某个项目的 S0–S7 固定推广到所有项目。
- 从相关项目说明和 AGENTS.md 获取路径、环境、资源及验证要求；不把先前项目的数据、GPU 编号、模型结构或失败状态带入新项目。

## 用户可指定的子代理设置

**模型与推理强度分别解析**，每个字段采用以下优先级：

1. 用户最新明确指定的值；若包含步骤或角色覆盖，对相应子代理使用覆盖值。
2. 本次任务此前已确认的设置，包括用户已采纳计划中相应的配置。
3. 没有任务配置时，省略该覆盖字段，使用当前接口的默认/继承规则；不虚构一个固定型号，也不为普通缺省反复询问。

这份 skill 不规定默认型号或推理强度。只指定模型，不意味着也指定了推理强度；只指定推理强度，也不代表要改变模型。用户新指令优先于旧计划；在交接中记录生效配置，必要时同步计划，避免后续步骤恢复旧设置。

- 用创建接口的真实参数传入选择，不以任务文字代替配置。当前 `collaboration.spawn_agent` 使用 `model` 和 `reasoning_effort`；填写前核对可用模型及受支持的推理强度，不猜测未知模型别名。
- 当前接口显式覆盖模型或推理强度时，必须配合 `fork_turns="none"`。用精简任务说明、计划路径和上游交接文件补足上下文，不依赖完整聊天继承。未覆盖时可按任务需要选择继承方式。
- 使用其他子代理接口时核对等价字段；不把这些参数写入未经支持的全局配置文件。
- 独立审查、修复替补和派生子代理都遵守生效配置及角色覆盖。更换模型或推理强度时，新建符合配置的子代理并交接；不假设向旧代理发一句消息就能改变其运行配置。
- 有明确配置时不静默换模型、升档或降档。配置或模型不可用时报告具体缺口，保留已完成产物，不假称使用成功，也不静默改成主代理包办。
- 记录各字段的来源、请求配置和可核验的实际配置；使用环境继承时明确标注。接口未提供实际信息时记为未知，不能用模型自述作为证明。
- 本任务选择不自动成为其他项目的永久默认值；不修改用户全局模型设置。

## 组织计划与执行

1. **确认已有工作。** 优先用只读子代理检查相关代码、改动、数据、结果和作业。已有步骤以复核、接收为主，不能为了重新分工而重复实现或训练。
2. **定义可验收步骤。** 按独立交付物拆分，写清依赖、输入、允许修改范围、输出和验收。紧密相关的算法、接口和掩码放在同一任务中，不按文件数量或代码行数机械拆分。
3. **每步派专属子代理。** 主代理维护步骤与负责人映射。主代理协调、整合和验收，不能把全部步骤自行实现后将子代理仅作装饰性审查。
4. **控制并行。** 无依赖的只读调查可并行；共享源码同一区域只有一个写入者。子代理共享工作区，不能假设天然隔离。实际并发与训练资源服从环境及用户限制。
5. **接收结果并核验。** 读取交接和必要证据，区分已实现待审查、验收通过、需修复、受阻。依赖步骤只使用已接受的产物。
6. **独立审查关键结果。** 关键实现、评估协议/结论和最终可复现交付，由未承担该实现的子代理审查。小型低风险步骤由主代理核对即可，不为每个微小改动增加审查轮次。
7. **完成交付。** 汇总实际改动、验证、产物路径和限制；指出仍在运行的作业及负责人。没有新增失败或疑点时，不反复运行相同检查。

如果需要将复杂步骤再拆分，保持依赖和负责人清楚；避免为简单工作增加多层子代理。

## 每步如何传上下文

为每步准备一份精简任务书，填写实际路径和值，交给子代理前去掉占位内容：

- 步骤编号、目标、依赖和主代理已接受的关键决定。
- 项目目录、读取顺序、上游交接、相关源码/配置/数据/权重身份。
- 允许写入的位置、必须保持的行为和资源限制。
- 已有作业及状态证据，避免重复启动。
- 要执行的验证、通过条件、输出位置与下一步将使用的接口。

不要把完整旧对话和长日志复制给每个子代理。正文保留必要决定，细节用可访问的文件引用；没有共享文件时，把完成任务所需的契约和证据内嵌传递。

按用户和项目约定选择计划及产物目录。通常只需一份进度记录和每步一份交接说明，不新建复杂的任务平台或重复复制已有数据。

每步交接记录：

1. 负责人、请求模型/推理强度、可核验实际配置、步骤状态。
2. 输入与基线身份，实际改动及原因。
3. 执行命令、退出码、日志与产物路径；关键指标注明比较条件。
4. 验收逐项通过/失败/未运行及对应证据。
5. 未解决问题、仍在运行的作业、下游可使用的结果与不能假设的结论。

输入身份按实际风险记录：例如 commit 加工作区差异、配置版本、数据 manifest 或 checkpoint hash；没有 Git 时使用相关文件清单/hash，不为形式完整扫描全部大数据。

## 审查、修复和中断恢复

- 自测通过不等于独立验收通过。审查子代理核对真实实现和证据，不仅复述实现者结论。
- 问题交回对应子代理，包含触发条件、影响、最小修复方向和回归要求。原子代理可继续本步骤；替补子代理读取同一交接链并使用当前生效的配置。
- 不以删除测试、隐藏失败或随意放宽数值阈值来完成验收。若验收契约本身不合理，先保留反例和证据，由主代理明确修订并重新审查。
- 重复失败时调整任务边界或形成具体缺口，不无限追加实验；已有预算和停止条件优先。
- 训练、评测等长作业与子代理状态分开：子代理返回或对话结束，不代表作业完成或停止。继续工作前核对实际进程身份、日志、恢复状态和产物，不凭旧 PID 或单一状态文件下结论。
- 中断后先读进度与交接，复用正确产物，从未完成步骤继续。上游契约改变时只重验受影响部分，不机械重跑全流程。

## 最终回复

给出本轮完成结果、主要证据、实际产物入口和必要限制。只完成计划时，链接计划并提供一个可复制的执行指令；执行已完成时，链接交付物，不再安排无依据的新工作。不要承诺固定额度节省比例。
