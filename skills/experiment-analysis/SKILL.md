# 实验分析

把已有实验产物整理成可追溯的比较和结论。使用普通文件、Python 脚本和 Markdown；不要求 Notebook 或客户端文档工具。按问题复杂度选择必要步骤，简短问题直接回答，不强制生成完整报告。

## 读取与对齐

- 先明确本次问题：方法对比、消融、训练表现、失败案例，或效率开销。
- 优先读取用户指出的结果、已有汇总脚本和相关配置；按需检查日志与原始输出，避免扫描无关目录或加载整个数据集。
- 记录结果来源：文件路径、实验编号、方法、数据划分、随机种子、关键配置，以及可获得的代码版本和评估命令。
- 核对指标定义、优劣方向、单位、聚合方式与 checkpoint 选择规则。区分训练和评估指标、验证集和测试集、best 和 last。
- 比较口径不同就注明差异；关键条件未知且影响判断时，先说明可得结论的范围，再索取必要信息。

## 比较与解释

- 用简洁表格列出实际结果、基线和差值；百分比指标区分百分点差值与相对提升。
- 有多个种子或重复运行时，保留逐次结果，并按需给出次数、均值和波动。单次运行只支持本次观察，不能据此声称稳定提升。
- 缺失值标为缺失，说明重复记录或解析失败；结果为空时指出具体缺口，不填零、不补造数值。
- 训练曲线关注收敛、波动、过拟合迹象及训练/验证差异。异常解释作为假设，并指出可验证的证据。
- 消融结论对应实际改变的因素；多个因素一起变化时，不把提升归因于某一个模块。
- 默认进行描述性比较。统计显著性、因果或机制结论需要对应的实验设计与证据；不能仅凭分数上涨给出。
- 对速度、显存或参数开销，报告已测量数据和测量条件；未知项直接注明。

## 脚本与图表

- 需要解析或聚合数据时，优先复用项目已有代码与环境；只有重复使用有价值时才保存独立 Python 脚本。
- 记录输入、筛选、聚合和输出路径，让结论能够由原始结果复现。保持原始日志和结果文件完整。
- 用户需要图表，或图表能帮助判断趋势时，结合已安装的 `scientific-visualization` 技能；标明轴、单位、运行次数和误差带含义。
- 分析已有结果不自动授权重新训练、运行昂贵评估、安装依赖或修改模型实现。

## 报告

根据任务选择以下内容，避免机械填满空章节：

1. 实验问题与数据来源。
2. 比较条件、指标定义和已知差异。
3. 结果表及必要图表。
4. 主要观察，每项关联到实际数字、文件或图表。
5. 局限、尚未证实的解释和有依据的后续实验建议。

需要保存时，采用用户指定位置或项目已有实验报告目录，优先更新已有报告。交付时给出报告/图表路径，以及实际执行的分析命令；明确未执行的检查。不要把“已整理结果”描述成“已复跑验证”。
