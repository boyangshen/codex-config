# 实现 agent 交接模板

仅在需要生成给 Gemini 或其他实现 agent 的独立任务书时读取本文件。将任务背景、契约、验收和材料替换成当前任务内容；省略不适用项，不让用户拼接前序长对话。

任务依据可以是共享文件或直接内嵌内容。另一 agent 无法访问共享文件时，内嵌必要片段与接口定义。以下尖括号是编写任务书时的模板变量，不是需要原样交给实现者的占位任务。

```text
你是本轮实现 agent。按以下已经确定的任务契约完成实现和必要验证，交付代码差异及事实性记录。

项目目录：<本轮已确认的项目目录；无法共享文件时改为内嵌必要内容>
首先读取：<真实任务书/审查文档路径，按读取顺序列出；内嵌内容则写明>
任务：<编号与具体目标>
背景与依据：<目标、必要材料、已确认方案或审查编号>
基线：<commit/diff/当前工作区及已有改动；无法读取时说明>
修改范围：<模块与必要调用点>
必须保持的行为：<与本轮相关的不变量>
关键实现契约：<输入输出、状态、异常、数学/数值或兼容性>
验收：<具体场景、预期观察及必要测试；区分必须项和环境依赖项>
依赖与未决问题：<没有则说明无>
提交策略：<默认保留工作区改动；已有本地提交授权则写明>
结果交接：<明确回写的记录文件路径，或要求返回的事实性交接内容>

执行要求：
1. 先检查材料、现有实现和已有改动，复用已正确的部分，保留其他人的改动。
2. 按本任务完成必要实现与接线，不自行扩展架构或更改关键语义。普通可逆细节自主处理；关键契约存在歧义时提出具体问题和建议，继续可独立推进的工作。
3. 发现必须修改范围外的依赖时，说明原因和最小必要变更。不要通过大范围重构绕过问题。
4. 不删除、弱化或跳过验收来宣称成功。有已知 bug 时优先保留能暴露它的反例；发现验收自身矛盾时提供证据。
5. mock 可用于隔离接口；功能若可能被门控、回退、固定输出或缓存绕过，必须证明目标路径真实启用，并保留与要求相符的集成验证。
6. 实际执行合适的检查。没有运行、环境不具备或仍有失败时明确标出，不编造通过结果或性能收益。
7. 本轮完成后返回简短交接：基线与实际改动文件、按任务/问题编号说明的结果、验收标准对应的命令和实际结果、未运行项和剩余问题。
8. 自测通过标为“已实现待审查”，不要冒充独立验收通过。若受阻，说明具体缺口和已完成部分。
```

审查后修复时，只保留仍需处理的问题和必要上下文。每个问题写清触发条件、影响、最小修复方向及回归要求，避免让实现 agent 重新猜测设计。

实际输出时必须替换以上模板变量，用户应能整段复制后交给 Gemini，无需补填路径或另找前序消息。规划/审查的最终回复都附上该独立代码块；审查通过则改写成验收交接，不安排无依据的新实现。
