# 多步骤实施计划

交付一份另一个执行者能够直接使用的 Markdown 计划。计划保留必要技术细节与证据，步骤按交付物和依赖划分，每一步明确专属执行子代理的职责；主代理负责协调和验收。

本 skill 负责规划。用户只要求计划时，可以只读调查和审查，但不开始实现、训练、评测作业或修改运行中的任务。用户已经明确要求规划后继续实施时，完成可执行计划后再按授权进入执行，不人为增加批准环节。

## 了解现状和约束

1. 读取用户最新目标、现有方案、相关 AGENTS.md 和必要的项目材料。确定交付边界、文档位置、资源限制及必须保留的行为；已有明确选择不重复询问。
2. 优先更新已有主计划。没有主计划时，在用户指定目录生成一份有明确名称的 `.md`；未指定时按项目文档约定选择，仍不明确则放当前项目工作目录并告知路径。不要制造内容重叠的多个计划。
3. 区分已经完成、已实现未验证、正在运行、失败和未知。现状附检查时间与证据路径；未核实进程时不凭旧状态文件断言它仍在运行或已经退出。
4. 读取足够材料以固定关键设计，不为规划扫描全部日志、下载整套数据或运行昂贵实验。涉及未知事实时做必要查证；仍无法确认的写成明确假设、待核实项或前置调查步骤。
5. 关键歧义影响范围或正确性时提出具体问题，同时推进不依赖答案的部分；可逆实现细节自主决定。

## 子代理与模型选择

规划期间可将相互独立的只读调查或计划审查交给子代理；不因写计划就提前启动所有执行子代理。

模型与推理强度分别采用：用户最新指定（包括角色/步骤覆盖）→ 本任务已确认设置 → 运行接口默认/继承。没有指定时，不把规划主代理的当前型号写成未来执行的固定要求，也不在 skill 中规定永久默认型号。

显式指定时使用当前接口支持的实际配置字段。对 `collaboration.spawn_agent`，模型/推理强度覆盖使用 `model`、`reasoning_effort` 并配合 `fork_turns="none"`；通过任务说明传递上下文。配置不可用时说明缺口，不静默替换。

计划中写清已确认的模型策略及来源；用户尚未指定的字段写“执行时按用户指定或环境继承”，避免让后续执行者误把示例配置当成约束。

## 构建计划

编写正文时读取 [计划结构与步骤模板](references/plan-template.md)，按任务删去无关部分，不机械填满模板。

- 先讲目标和最终行为，再说明设计、现状、步骤、验证与交付。引用真实项目路径；拟创建的路径标为计划产物。
- 定义关键接口和不变量：按任务需要明确张量/数据格式、字段语义、单位、状态、错误处理、兼容性或数学/数值约束。
- 给出可执行的技术选择和理由。未决定的设计列出需要哪项证据才能作出选择，不能把多个互斥方案都写成已确定实现。
- 按独立可验收结果拆步骤，说明依赖及可并行部分；步骤数量由工作量决定，不固定成八步，也不为每个函数单独建步骤。
- 每一步写清负责人、输入、要做的工作、允许修改范围、产物、验收和交接。相互关联的算法、掩码、接口与调用链应一起验证。
- 复用正确代码、数据、模型和结果；已完成步骤安排审查接收，失败阶段安排定位与恢复，而不是重做全部工作。
- 训练/实验计划需有数据划分、目标和损失、对照、指标定义、模型选择规则、资源预算和停止条件。估计时间标明依据，不虚构确定时长。
- 代码计划需有关键行为、依赖、相关测试和集成验收。验证聚焦实际风险，不用与实现逐行对应的测试数量冒充质量。
- 主代理维护输入与决策，专属子代理执行每步。关键实现、评估和最终交付安排独立审查；同一源码区域只有一个写入者。

## 交接和验收

计划必须说明上下文如何从上游传到下游：任务说明包含决定、输入身份、实际路径和验收标准；结果交接包含改动、命令/退出码、产物、指标、未运行检查、限制及仍在运行的作业。

主代理先验收上游产物，再交给依赖步骤。自测通过与独立验收通过分开；失败返回原步骤修复，保留反例和证据。中断后核对已有进度和作业，再从未完成位置继续。

将交接文件放在符合项目约定的位置。通常一份进度记录加每步一份交接足够，不为计划另建执行平台，不复制大数据或全部聊天历史。

## 检查计划是否可执行

- 每步能否凭输入材料开工，产物能否被下游消费？依赖是否有环，重要集成是否遗漏？
- 验收是否对应用户目标，是否给出了可观察的通过/失败条件，而非“正常”“效果不错”之类空泛描述？
- 技术细节、字段/维度、比较口径和资源限制是否一致？是否混淆已完成事实与未来计划？
- 是否保留用户最新的范围与模型选择，是否把单个项目的约束误用成通用要求？
- 如果任务复杂，安排独立只读子代理审查计划；先修正实质问题，再交付。不要为简单计划强制增加多轮审查。

## 交付

输出实际 Markdown 路径、关键决定和真正需要用户补充的事项。附一段填写好计划路径的简短执行指令，明确下一阶段按计划分派子代理；不能把尚未创建的路径或占位变量交给用户自行拼接。

可用 `subagent-plan-execute` 消费这份计划；它未安装时，计划本身仍须包含足够的分工、交接和验收要求。本轮若仅规划，应明确没有启动计划中的实现或实验。
