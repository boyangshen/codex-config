# 项目存储

项目源码、脚本、配置和依赖清单放在当前机器惯用的个人代码工作区。安装后的环境、数据集、权重、检查点和运行结果放在实际挂载的存储盘。两类目录都按机器确定，也可以位于同一个挂载点下。

1. 已有项目沿用其仓库位置。新建项目时，根据用户指定的位置、当前工作目录及相邻仓库判断个人代码工作区。`projects` 和 `myProjects` 都是可能的目录名。遇到符号链接时查看实际落点，保留用户惯用的访问路径。
2. 查看项目已有的路径配置和本机挂载。用 `findmnt -T <已有目录>` 核实目标所在的文件系统，用 `df -h <已有目录>` 查看可用空间，并检查写权限。`/data` 和 `/memory` 只是挂载点示例。在适合该任务的盘上复用个人目录，按需创建子目录；环境、数据和结果可以分盘存放。
3. 创建环境或启动任务前，把路径传给实际写文件的工具。例如用 `python -m venv <存储根>/envs/<项目名>` 创建环境，将模型下载缓存指向盘上已有缓存，并将训练的输出目录设为 `<存储根>/outputs/<项目名>/<运行名>`。日志、评估指标和导出文件随该次运行保存。跨机器共享代码时，通过配置或环境变量传入本机路径。

如果现有约定足以确定路径，直接沿用。如果多个工作区或存储位置同样合理，或预期的盘未挂载，先列出候选路径并询问用户，再创建目录或写入。已有文件的迁移由用户另行指定。
